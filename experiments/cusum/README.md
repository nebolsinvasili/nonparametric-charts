# CUSUM-SN и CUSUM-SR: алгоритмы и опыты

Каталог содержит вычислительное сопровождение CUSUM-карт:

- точный марковский расчёт распределения длины серии (RL);
- OC-кривые `ARL(δ)`;
- подбор `h` и совместный подбор `(k, h)`;
- замеры производительности;
- кросс-валидацию Python ↔ R (`npSPC`);
- генерацию данных для отчёта.

Первоисточник: Chakraborti & Graham (2019), *Nonparametric Statistical
Process Control*, § 4.2.2, стр. 202–208; примеры — § 4.3.2, стр. 229–243;
выбор `(k, h)` — § 3.2.2, стр. 67–72.

## Статистики и карты

### CUSUM-SN

```text
SN_t = 2T_t − n,          T_t ~ Bin(n, p),  p = P(X ≥ μ₀)
S_t⁺ = max(0, S_{t−1}⁺ + SN_t − k),   S_0⁺ = 0
S_t⁻ = min(0, S_{t−1}⁻ + SN_t + k),   S_0⁻ = 0
```

Сигнал: `S_t⁺ ≥ h` или `S_t⁻ ≤ −h`. В IC `p = 0.5`, `E[SN] = 0`.

### CUSUM-SR

```text
SR_t = 2T_t⁺ − n(n+1)/2
S_t⁺ = max(0, S_{t−1}⁺ + SR_t − k)
S_t⁻ = min(0, S_{t−1}⁻ + SR_t + k)
```

`T_t⁺` — статистика знаковых рангов Уилкоксона. Требуется симметрия
распределения; в IC `E[SR] = 0`.

Ссылки: ур. 4.7–4.12, стр. 202–206. Для нижней ветви SR используется `+k`
(в печатной ур. 4.11 опечатка `−k`; см. `docs/reports/cusum_plan.md`).

## Точный расчёт длины серии

### Пространство состояний

Непоглощающие состояния:

- верхняя карта: `S⁺ ∈ {0, step, 2·step, …}`, `S⁺ < h`;
- нижняя: `S⁻ ∈ {0, −step, …}`, `S⁻ > −h`;
- двусторонняя: пары `(S⁺, S⁻)` с `S⁺ ≥ 0`, `S⁻ ≤ 0`,
  `S⁺ < h`, `S⁻ > −h`.

Стартовое состояние `(0, 0)` всегда стоит первым в матрице. Это важно:
расчёт RL берёт `start[0] = 1`, и старая ошибка сортировки занижала
двустороннюю `ARL` (ADR-025).

### Матрица переходов

`Q[i, j]` — вероятность перейти из состояния `i` в `j`, не выйдя за
границы. Выход за `±h` — поглощение (сигнал). Матрица строится по
распределению шага `Z_t`.

Для `SN`/`SR` носитель дискретен, поэтому переходы считаются точно, без
численного интегрирования. Для `SR` при сдвиге используется точная
квадратура по порядковым статистикам `|X|` (при `n ≤ 20`) либо Монте-Карло.

### ARL и распределение

```text
ARL = ξ (I − Q)⁻¹ 1,       ξ = (1, 0, …, 0)
P(N = t) = ξ Q^{t−1} (I − Q) 1
E[N²] = ξ (I + Q)(I − Q)⁻² 1
SDRL = sqrt(E[N²] − ARL²)
```

Ссылки: ур. 3.22–3.24, стр. 112. PMF усекается по `max_quantile`; ARL от
усечения не зависит.

### Оптимизация без PMF

При подборе `(k, h)` распределение длины серии не нужно — достаточно `ARL`.
Поэтому `cached_arl` вызывает `_cusum_arl`, который:

1. строит пространство состояний и `Q`;
2. проверяет достижимость поглощения;
3. решает `(I − Q)a = 1` и возвращает `a[0]`.

PMF, `SDRL` и перцентили не считаются. Публичный `cusum_run_length` при этом
не меняется.

Дополнительно:

- `Q` строится векторизованно (`numpy`);
- если все шаги и `k` лежат на сетке `0.5`, состояния — точные двоичные
  дроби, округление не выполняется;
- для дробного `k` округление состояний сохранено;
- результаты совпадают с прежним скалярным расчётом (проверено тестами).

## Подбор `h`

`design_h` работает по решётке `h = step · i`, где `step` — НОД приращений
`Z − k` (`_lattice_step`). Для `SN`/`SR` шаг часто равен `2`, но зависит от
чётности `k` и значений статистики.

Алгоритм:

1. `i = 1, 2, 4, 8, …` — экспоненциально расширяем верхнюю границу, пока
   `ARL(h) ≥ ARL_IC` или не достигнут `max_candidates`.
2. Бисекция по индексам: находим первый `i`, где `ARL ≥ ARL_IC`.
3. `conservative` (по умолчанию): берём предыдущий узел с `ARL ≤ ARL_IC`.
   Если `ARL` точно равна номиналу, плато просматривается до первого
   роста.
4. `nearest`: сравниваем соседние узлы по `|ARL − ARL_IC|`.
5. Если монотонность нарушена или сигнал недостижим — fallback на прежний
   линейный скан.
6. Если ни одно `h` не даёт `ARL ≤` номинала, возвращается ближайшее сверху
   и заполняется `note`.

Монотонность `ARL(h)` при фиксированном `k` проверена тестом
`test_arl_is_monotone_in_h`. Номинал может быть недостижим точно: `ARL(h)` —
ступенчатая функция.

## Подбор `k` из целевого сдвига

`design_k_from_shift(n, target_arl, delta, statistic=...)` — порядок
«как на реальной задаче»: `k* = E[Z_δ]/2` (`reference_k`) привязывается к
решётке статистики (шаг `z_step / 2` = 1 для `SN`/`SR`), после чего
проверяются три соседних узла `k* ± step`. Выбирается узел с
`ARL_IC ≤` номинала, попадающий в допуск `tol` (по умолчанию 10 %) и
ближайший к `k*`; если в допуск не попадает никто — ближайший к `k*` узел
с `ARL_IC ≤` номинала, причина пишется в `note`.

Возвращается `DesignResult` с полями `k`, `h`, `arl`, `k_star`,
`lattice_step`, `candidates`. Пример для `n = 14`, `ARL_IC = 500`,
`δ = 1.5`:

```text
SN: k=6, h=6, ARL_IC=409.0   (номинал на решётке недостижим)
SR: k=49, h=46, ARL_IC=497.7
```

Для `SR` простое округление `k* = 50.023` дало бы `k = 50` и
`ARL_IC = 410.9` — заметно хуже по бюджету, поэтому выбор идёт по паре
`(k, ARL_IC)`, а не по одному `k*`.

## Совместный подбор `(k, h)`

`design_kh`:

1. Строит распределения статистики в IC (`δ = 0`) и при целевых сдвигах
   `δ`.
2. Кандидаты `k`:
   - по умолчанию `k = frac · E[Z_δ]`, `frac ∈ {0.25, 0.375, 0.5, 0.625,
     0.75, 1.0}` — непараметрический аналог `k = δ/2`;
   - значения привязываются к решётке статистики;
   - можно передать `k_values` явно.
3. Для каждого `k` подбирает `h` процедурой выше.
4. Считает `ARL_OOC` для каждого `δ`; критерий — максимум по `δ`
   (минимакс при сетке).
5. Отбрасывает варианты с `relative_error_ic > tol` (`tol = 0.10`).
6. Выбирает допустимую пару с минимальным `ARL_OOC`; при равенстве —
   меньшее отклонение `ARL_IC`, затем меньший `k`.

Порядок соответствует книге: `k` первым, затем `h` под номинал; оптимальна
пара с минимальным `ARL_OOC` (§ 3.2.2, стр. 71–72). Минимакс по сетке `δ` —
обобщение, а не буквальная процедура книги.

## Скрипты

### `01_oc_curves.py`

Строит `ARL(δ)` для:
- CUSUM-SN: `n=5`, `k=1`, `h=4`, верхняя, пример 4.8;
- CUSUM-SR: `n=4`, `k=2`, `h=6`, верхняя, пример 4.10.

Распределения: normal, `t`, Laplace, logistic, uniform; для SN также gamma.
Сетка `δ = 0, 0.25, …, 3.0`. Печатает таблицы, сохраняет
`results/experiments/cusum_oc_curves.png`.

Ожидаемо: при `δ = 0` все распределения дают одну и ту же `ARL` (IC не
зависит от `F`); с ростом `δ` кривые расходятся.

### `02_sr_exact_vs_mc.py`

Сравнивает точное распределение `SR` под сдвигом с Монте-Карло:

- `δ = 0.25`;
- `n = 4, 6, 10, 20, 30`;
- `n_sim = 5 000 … 400 000`;
- 5 seed'ов.

Печатает ошибку распределения и `ARL`, разброс по seed'ам и время; сохраняет
`cusum_sr_exact_vs_mc.png`. Точный метод даёт ошибку порядка `10⁻⁸…10⁻⁹`,
Монте-Карло — `10⁻³`.

### `03_kh_design.py`

Печатает таблицы подбора `(k, h)`:
- SN: `n = 10, 15, 20`, `δ = 0.5, 1, 1.5, 2`;
- SR: `n = 5, 10`, `δ = 0.5, 1, 1.5`;
- `ARL_IC = 370, 500`, двусторонняя карта.

Строит `ARL_OOC(k)` и сохраняет `cusum_kh_design.png` и `.txt`. Это
регрессионная проверка подбора: числа должны совпадать при повторном запуске.

### `04_performance.py`

Разбивает время полного расчёта RL на фазы:
- построение состояний;
- матрица `Q`;
- решение системы и развёртка PMF;
- итог.

Считает реперные варианты `n = 10, 20` и рост стоимости по `n = 5…30`
(3 прогона, берётся минимум). Дополнительно печатает время `design_kh` для
SN `n=10/20` и SR `n=10`. Сохраняет `cusum_performance.png` и `.txt`.

Ориентир: в полном расчёте основное время — PMF при больших `ARL`; в
подборе PMF не считается, и время определяется построением `Q`.

### `05_cross_validation.py`

Три уровня сверки с R-пакетом `npSPC`:
1. статистики `SN`/`SR` на одних данных;
2. кумулятивные суммы и индексы сигналов;
3. длины серий: имитация на общей выборке и точный марковский `ARL`.

Запуск с R:

```bash
R_LIBS=/tmp/opencode/renv/lib/R/library \
RSCRIPT=/tmp/opencode/renv/bin/Rscript \
poetry run python experiments/cusum/05_cross_validation.py
```

Без R, при наличии `experiments/cusum/xval/`:

```bash
poetry run python experiments/cusum/05_cross_validation.py --no-r
```

Результат — `results/experiments/cusum_cross_validation.txt`. Расхождения
фиксируются отдельно, без подгонки нашей реализации.

### `06_gen_figdata.py`

Генерирует LaTeX-макросы `docs/reports/cusum_macros.tex`: OC-кривые для
`SN n=10, k=6, h=4` и `SR n=10, k=41, h=14`, а также ступенчатую
`ARL_IC(h)`. Обычно запускается через `make cusum` в `docs/reports/`.

## Воспроизведение примера `n = 14`

```bash
poetry run python - <<'PY'
from nonparametric_charts.utils.run_length_design import design_kh

for statistic in ('SN', 'SR'):
    for target in (370.0, 500.0):
        r = design_kh(
            n=14, target_arl=target, delta=1.0,
            statistic=statistic, sided='two',
        )
        print(
            f'{statistic} {target:g}: k={r.k:g}, h={r.h:g}, '
            f'ARL_IC={r.arl_ic:.4f}, ARL_OOC={r.arl_ooc:.4f}'
        )
PY
```

Ожидаемо:

```text
SN 370: k=5, h=7, ARL_IC=353.3481, ARL_OOC=1.9887
SN 500: k=10, h=2, ARL_IC=546.1333, ARL_OOC=3.0850
SR 370: k=54, h=37, ARL_IC=355.4879, ARL_OOC=1.6246
SR 500: k=54, h=39, ARL_IC=464.9837, ARL_OOC=1.6965
```

Для SN при номинале 500 лучшая пара на решётке даёт `ARL_IC = 546.13`;
отклонение 9.2 % укладывается в `tol = 10 %`. Это не ошибка: номинал
недостижим точно из-за ступенчатой `ARL(h)`.

## Частые проблемы

**`05_cross_validation.py` не находит R** — установите окружение через
`setup_renv.sh` или используйте `--no-r` при наличии CSV.

**`design_kh` идёт долго** — проверьте `n`, `statistic` и `max_candidates`;
для SR при больших `n` матрица `Q` растёт. Не снижайте `max_candidates` без
необходимости: это может изменить результат.

**Другие `k`, `h`** — проверьте `delta`, `sided`, `ic_rule`, `tol` и версию
пакета. Время может отличаться, а `k`, `h`, `ARL` при тех же входах — нет.

**Overfull в отчёте** — см. `docs/reports/README.md`; правьте текст, а не
макросы, сгенерированные `06_gen_figdata.py`.
