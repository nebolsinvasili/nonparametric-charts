## Как пользоваться

- Перед реализацией метода открыть соответствующий раздел, выписать формулы и
  правила сигнала, зафиксировать ссылку в докстринге кода.
- Для определений FAR/ARL/MRL — раздел 2.1.12 (стр. 39–50).
- Для Case K/U — раздел 2.1.9 (стр. 37).
- Вторичный русский источник: В. Н. Клячкин, «Статистические методы в управлении
  качеством: компьютерные технологии» (`docs/ref/Klyachkin_...pdf`).

## Рабочие документы карт

Детальные досье и журнал прогресса по картам — `docs/reports/<chart>_plan.md`
(не авто-подгружается). Текущие:

- CUSUM (§4.2.2, стр. 202–208; примеры §4.3.2, стр. 229–243) —
  `docs/reports/cusum_plan.md`. Реализованы `CusumSignChart` (CUSUM-SN,
  §4.2.2.1) и `CusumSignedRankChart` (CUSUM-SR, §4.2.2.4); примеры 4.6/4.7/4.9
  проверены. 3b.1–3b.7: марковский RL, симуляция, renewal, приближения,
  OC-кривые, подбор `h` и совместный дизайн `(k, h)` —
  `utils/run_length.py`, `utils/run_length_design.py`; OOC-распределение `SR`
  для `n ≤ 20` считается точно (квадратура), кэш ARL готов. Выбор `(k, h)` —
  §3.2.2, стр. 67–72 (`k = E[Z_δ]/2` как аналог `k = δ/2`; минимум `ARL_OOC`;
  консервативное `h`: `ARL_IC ≤` номинала). 3b.9 (тесты/производительность)
  готово: `tests/test_run_length_invariants.py`,
  `tests/test_run_length_performance.py`,
  `experiments/cusum/04_performance.py`. 3b.10 (кросс-валидация Python↔R)
  готово: эталон — `npSPC` (`cusum_sn`/`cusum_sr`), `experiments/cusum/
  05_cross_validation.{py,R}`; статистики совпадают точно, сигналы 918/918,
  ARL по общим данным совпадает. При сверке исправлен баг двусторонней цепи
  (ADR-025). Далее — 3b.11 (документирование/отчёт).
  Открыто: рис. 4.6 (`n=10, k=41, h=24`) не воспроизводит `ARL≈500`
  (точный расчёт `≈80 600`; подбор под 500 даёт `h=14` при `k=41`, `k=39`).
