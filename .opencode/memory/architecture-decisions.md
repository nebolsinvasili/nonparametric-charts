# Архитектурные решения (ADR)

Журнал решений: **что** выбрано, **почему**, и — главное — **что было отброшено и
почему**. Отвергнутые варианты агент не может восстановить из кода, поэтому их надо
фиксировать явно. Формат: дата, статус, контекст, решение, альтернативы.

---

## ADR-001. Коэффициенты находятся автоматически

- **Дата:** 2026-10-17 · **Статус:** уточнено (см. правку ниже)
- **Контекст:** `BaseControlChart._load_coefficients` ищет файл по списку путей.
- **Решение:** путь `src/utils/coefficients.json` вычисляется в `_load_coefficients`
  от `__file__` (`.../src/utils/coefficients.json`), поэтому файл находится
  автоматически из любого каталога. Явный `coefficients_file` /
  `NONPARAMETRIC_CHARTS_COEFFICIENTS` нужны только для нестандартного расположения. Для
  непараметрических карт значения коэффициентов **не используются** (это константы
  параметрических карт).
- **Правка (2026-10-17):** ранее здесь ошибочно утверждалось, что такого пути в
  списке нет и файл нужно передавать явно. Проверка исходника `base_chart.py`
  показала обратное.
- **Отвергнуто:** удаление `coefficients.json` (ломает `BaseControlChart` и общий
  интерфейс карт).

## ADR-002. Запуск из корня, абсолютные импорты

- **Контекст:** нет `src/__init__.py`, нет установленного пакета `nonparametric-charts`

- **Отвергнуто:** превращение в устанавливаемый пакет `nonparametric-charts`; относительные импорты

## ADR-003. Стиль графиков — `src/utils/plot_style.py`, `mathtext` вместо `usetex`

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** нужен минималистичный LaTeX-вид; подписи и легенды — на русском.
- **Решение:** единый модуль `plot_style` (`apply_minimal_latex_style`, `despine`,
  `PALETTE`), serif + `mathtext.fontset='cm'`, `usetex=False` по умолчанию.
- **Отвергнуто:** `usetex=True` по умолчанию (тянет TeX-пакеты и ломает кириллицу);
  настройка rcParams отдельно в каждом классе/ноутбуке (разъезжается стиль).

## ADR-004. Каркас ноутбука и двойное представление формул

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** требование: ноутбук = теория + код + разбор + логика + формулы + графики.
- **Решение:** фиксированный порядок разделов (`rules/notebook-style.md`); каждая

## ADR-005. Память и правила — в `.opencode/`

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** `AGENTS.md` быстро разрастается и теряет смысл; нужна «долговременная
  память» между сессиями и жёсткие правила вне промпта.
- **Решение:** `AGENTS.md` — указатели + жёсткие правила; детали — в
  `.opencode/rules/`, знания — в `.opencode/memory/`, процедуры — в
  `.opencode/skills/`, шаблоны — в `.opencode/templates/`. `rules/*` и `memory/*`
  подключаются через `instructions` в `opencode.json`.
- **Отвергнуто:** сваливать всё в `AGENTS.md`; хранить память только в голове агента.

## ADR-006. Точечная сверка с книгой через `book-lookup`

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** ссылки на книгу нужны точные (раздел + печатная страница), а в PDF

- **Решение:** навык `book-lookup` со скриптом `lookup.py` (поиск по regex/странице,

- **Отвергнуто:** ручной пересчёт страниц и поиск «на глаз».

## ADR-007. Выбор константы `a`: наименьшее достижимое значение

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** `_calc_a_conservative`/`_calc_a_symmetric` перебирали `a` сверху
  вниз и возвращали **наибольшее** подходящее (при n ≥ 10 это давало `a = n`),
  а при недостижимости целевой вероятности — ошибочный fallback `a = 1`.
- **Решение:** перебирать `a` снизу вверх по **достижимым** значениям (та же
  чётность, что `n` для SN и `S = n(n+1)/2` для SR) и брать первое с
  `P(· ≥ a) ≤ FAR₀/2`. Если недостижимо (малое n) — `a = n` (SN) или `a = S` (SR),
  как в книге для n = 1 (стр. 190) и примера 4.4 (n = 4, a = S = 10).
- **Отвергнуто:** оставить `a = n` для всех n ≥ 10 (расширяет границы, теряет
  чувствительность); fallback `a = 1` (практически бесполезные границы).
- **Тесты:** `tests/test_control_constant_selection.py`.

## ADR-008. Тесты — по примерам книги, артефакты в `results/tests/`

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** в `tests/` лежали побайтовые копии параметрических тестов
  (`median/r/s/xbar`) и знаковый тест под старый API; модули не импортировались.
- **Решение:** один тестовый файл = один пример из книги (примеры 4.1–4.3 —
  `tests/sign/`, 4.4–4.5 — `tests/signed_rank/`), в шапке — описание и объяснение
  со ссылкой на раздел и печатную страницу; построенные карты сохраняются в
  `results/tests/` с номером примера. Фикстура `results_dir` — в `conftest.py`.
- **Отвергнуто:** держать параметрические тесты здесь (они относятся к
  `../parametric-charts`); свалка примеров в одном файле.

## ADR-009. Границы репозитория: только непараметрические карты

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** `signed_rank_chartTTT.py` — побайтовый дубликат старого класса
  `SignRankChart` (нормальная аппроксимация Уилкоксона) из `../parametric-charts`,
  нигде не импортировался.
- **Решение:** удалить дубликат; в этом репозитории — только `SignChart` и
  `SignedRankChart`. Параметрические карты — в `../parametric-charts`.
- **Отвергнуто:** оставлять «черновик на всякий случай» (мусор, риск расхождения).

## ADR-010. Единое имя проекта — `nonparametric-charts`

- **Дата:** 2026-10-17 · **Статус:** принято
- **Контекст:** проект назывался `ShCC`, репозиторий — `noparametric-charts` (опечатка
  без «n»), а в сохранённом выводе ноутбука фигурировал старый путь
  `~/Projects/nparametric-charts`. Три разных написания одного и того же.
- **Решение:** везде — имя `nonparametric-charts`: `pyproject.toml` (`name`),
  `AGENTS.md`, `.opencode/rules|memory`, докстринги/тесты. Технический
  идентификатор `SHCC_COEFFICIENTS` переименован в
  `NONPARAMETRIC_CHARTS_COEFFICIENTS` (`src/base/base_chart.py`, `conftest.py`,
  документация). Jupyter-kernel — `nonparametric-charts-py`. Локальный каталог
  переименован в `nonparametric-charts`, `git remote` обновлён.
- **Отвергнуто:** оставлять сокращение `ShCC` (не совпадает с именем репозитория);
  «полу-переименование» (одна часть `ShCC`, другая — `nonparametric-charts`).
- **Внимание:** репозиторий на GitHub нужно переименовать вручную, иначе push по
  обновлённому URL не пройдёт. Старая env-переменная `SHCC_COEFFICIENTS` больше не
  читается.

## ADR-011. Подписи зон в единицах σ — это соглашение, а не оценка σ

- **Дата:** 2026-10-17 · **Статус:** принято (с оговоркой)
- **Контекст:** на картах `SignChart`/`SignedRankChart` полосу от CL до контрольной
  границы `a` делили на трети и подписывали «Зона A/B/C». Пользователь попросил
  подписи «через сигму». Но `a` здесь выбирается из условия на FAR
  (§4.2.1.1, формула выбора `a`, печ. с. 191; §4.2.1.2, печ. с. 198), а **не**
  равно 3σ:
  - знаковая: SD(SN) = 2·sqrt(n·p(1−p)); при p = 0.5 (IC) SD = sqrt(n)
    (§4.2.1.1, Table 4.1, **печ. с. 193**);
  - знаково-ранговая: SD(SR) = sqrt(n(n+1)(2n+1)/6)
    (§4.2.1.2, таблица распределительных свойств, **печ. с. 199**).
  Примеры: sign n=5 → a=5, 3σ≈6.71; sign n=10 → a=10, 3σ≈9.49;
  sign n=20 → a=14, 3σ≈13.42; SR n=4 → a=10, 3σ≈16.43.
- **Решение:** по требованию пользователя оставить подписи в единицах σ, трактуя
  `σ = a/3` как соглашение о разметке (аналог вестерн-электриковских зон;
  в книге зоны A/B/C определены именно от 3σ — гл. 3, печ. с. 92–93). В
  докстрингах зафиксировано «σ = a/3». Формулы истинных SD — см. выше.
- **Отвергнуто:** подписывать зоны через `a` (`2a/3…a`) — менее привычно
  пользователю; молча называть `a/3` «σ» без оговорки — методологически неверно.
- **Оговорка:** если понадобится строгая σ-разметка, границы нужно ставить на
  реальных 1σ и 2σ (формулы выше), а не на `a/3`, `2a/3`.
