# Humanizer RU — очеловечить русский текст

Правка готового текста (отчёт, план, память, ноутбук, докстринги) без изменения
смысла. Опирается на признаки AI-текста из Wikipedia «Signs of AI writing», но
с русским материалом: канцелярит, отглагольные существительные, кальки.

## Когда использовать

- Текст «звучит как отчёт для галочки»: много «является», «осуществляется»,
  «производится», «в рамках», «с целью».
- Нужно заменить англицизм или кальку (`подбор`, `перформанс`, `фича`).
- Перед сдачей отчёта, плана, README или ноутбука.

## Что править

1. **Канцелярит.** `осуществляется подбор` → `подбираем`; `производится расчёт`
   → `рассчитываем`; `является важным` → `важно`.
2. **Отглагольные существительные.** `выполнение проверки` → `проверяем`;
   `обеспечение воспроизводимости` → `чтобы результат воспроизводился`.
3. **Нанизывание родительных падежей.** `процесс расчёта значений параметров
   карты` → `расчёт параметров карты`.
4. **Пассив без агента.** `было установлено, что` → `установили, что` (если
   агент известен) или `оказалось, что`.
5. **Штампы AI-прозы.** `важно отметить`, `стоит подчеркнуть`, `не просто X, а Y`,
   `играет ключевую роль`, `является свидетельством`, `в современном мире`.
6. **Списки ради списков.** Три пункта, где хватит одного предложения, — свести
   в предложение. Симметричные триады — разбить.
7. **Англицизмы без нужды.** `перформанс` → `производительность`; `фича` →
   `возможность`; `бенчмарк` → `замер`. Технические идентификаторы
   (`design_h`, `ARL`, `UCL`) не переводить.
8. **Пустые зачины.** `В данной работе рассматривается` → сразу к делу.

## Что нельзя менять

- Числа, формулы, единицы, названия методов, разделы и печатные страницы книги.
- Идентификаторы кода, имена файлов, команды, вывод программ.
- Смысл и структуру аргумента: правка только языковая.
- Стиль цитат из книги и подписи к рисункам, если они уже согласованы с LaTeX.

## Порядок

1. Прочитать фрагмент целиком, понять, что он утверждает.
2. Найти конкретные места (маркер + строка), а не «переписать всё».
3. Предложить замену в 1–2 вариантах, сохранив факты.
4. Проверить: не потерялся ли субъект действия, не поехали ли числа и ссылки.
5. Для кода — только докстринги/комментарии; поведение не трогать.
6. После правки прогнать проверки проекта (`pytest`, `make check`, ноутбук).

## Примеры

| Было | Стало |
| --- | --- |
| Англицизм «перформанс» в отчёте | «производительность» |
| Осуществляется расчёт длины серии | Длину серии считаем по марковской цепи |
| Важно отметить, что результаты являются воспроизводимыми | Результаты воспроизводятся |
| Данный подход обеспечивает возможность сравнения вариантов | Подход позволяет сравнивать варианты `(k, h)` |
